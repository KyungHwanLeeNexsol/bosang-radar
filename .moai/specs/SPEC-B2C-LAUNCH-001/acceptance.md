# Acceptance Criteria — SPEC-B2C-LAUNCH-001

Given-When-Then 형식이며 각 AC는 대응하는 REQ를 인용한다. 이 문서는 검증 계층이고 GEARS 요구사항은 `spec.md`에 있다.

각 AC에는 네 항목을 붙였다.

- **검증**: 실행 방법. 이미 있는 명령은 `package.json`에서 확인했다(`pnpm test`, `pnpm test:e2e`, `pnpm build`, `pnpm verify:flag-runtime`). 그 밖의 파일명·명령은 run-phase에서 확정될 **후보**다.
- **통과 판정**: 통과와 실패를 가르는 한 줄. 수치 기준을 이 문서에 쓰지 않는다.
- **선결**: AC가 의존하는 결정·산출물. **선결이 충족되지 않은 동안 AC는 BLOCKED이며 통과로 계산하지 않는다.** BLOCKED는 실패도 통과도 아니다.
- **서명**: 사람의 확인이 필요한 AC의 역할. 서명 기록은 확인 대상·역할·날짜·대상 값을 담고 법적 결론을 담지 않는다.

"시험 수행"은 로컬 파일 DB와 로컬 서버에서 하는 것이며 운영에는 접근하지 않는다. 운영 호스트나 운영과 동등한 별도 호스트에서 관측·변경을 실제로 수행하는 일, 그리고 `deploy.yml` 변경을 `main`에 올려 운영 배포를 일으키는 일은 별도의 운영 행위이며 이 SPEC의 AC가 아니다. AC는 **절차와 판정선**(기록이 유효하려면 무엇을 담아야 하는가, 점검기가 무엇을 막는가, 절차 문서가 무엇을 적어야 하는가)을 로컬 fixture와 문서로 판정한다. 이 문서의 어떤 AC도 지금 통과로 주장되지 않는다.
