## 읽는 순서

원격 DB 시험의 절차는 백업 → 마이그레이션 0009 적용 → `run` → `cleanup` → `revert-schema` → 복구 뒤 백업 대조다(런북 §12.8·§12.9).

1. `run-output.txt` — T1~T7 각 케이스의 `ok`/실패 줄과 마지막의 `게이트 7/7 통과`. 연락 희망 시간 검증은 T3·T4·T7의 `채널·연락 희망 시간` 줄이다.
2. `cleanup-output.txt`, `cleanup.json` — 시험이 만든 행만 지워졌고 총계가 baseline(0)으로 돌아왔다.
3. `revert-schema-output.txt` — 상담 테이블 두 개와 0009 마이그레이션 기록 1행만 지웠다.
4. `rollback-compare.md`의 비교 3 — 마이그레이션 직전 백업(b)과 복구 뒤 백업(c)이 13개 테이블과 스키마에서 일치한다.

## 시험 데이터

이 실행이 만든 행은 모두 가상이다. 요청 IP는 문서용 대역(`198.51.100.0/24`)이고, 연락처는 실제 가입자에게 배정되지 않는 `010-0000-xxxx` 대역의 값이며 응답에는 `010-****-000x`로 가려져 나온다. 이름은 `가상테스트-<run-id>` 형식의 가상 값이다. 연락 희망 시간은 `평일 오후 2시~4시`다.

## 이 폴더에 없는 것

- **접속 URL·토큰**: 처음부터 로그에 없다. 실행 때 접속 정보를 주입한 임시 래퍼가 출력의 URL·호스트·토큰을 `***`로 가렸고, 래퍼 파일 자체에도 값이 없었으며 실행 뒤 삭제했다.
- **운영 데이터**: 백업 본문, 운영 테이블의 행 수와 내용 해시는 올리지 않았다(`rollback-compare.md`에는 일치 여부만 있다).
- **시험 행 식별자 원장**(`ledger.json`)은 올리지 않았다. 정리 결과는 `cleanup.json`으로 확인한다.
- **저장하지 않은 출력**: 지문 확인(`fingerprint`), `db:migrate`, `preflight`, 백업 스크립트의 출력은 파일로 저장하지 않았다. 세션 중에 직접 확인했고 `progress.md` D-NEW-30 Claim 110에 요약했다. 이 폴더만으로는 그 부분을 독립적으로 확인할 수 없다.

- 이 파일들은 로컬 로그를 옮긴 것이다. 원본 로그는 gitignored라 원격 저장소에는 없고, 제3자가 원본과 대조할 방법은 없다.
