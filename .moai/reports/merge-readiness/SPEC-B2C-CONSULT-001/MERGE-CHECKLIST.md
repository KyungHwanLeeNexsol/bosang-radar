## 3. 마이그레이션 직전 백업과 실패 대응

### 3.1 무엇이 적용되나

`db/migrations/0009_abnormal_owl.sql`은 `consultation_rate_limits`, `consultations` 테이블과 유니크 인덱스 3개를 **만들기만 한다**(파일을 읽음). 기존 테이블은 바꾸지 않는다. 마이그레이션은 Drizzle `migrate`가 `@libsql/client`의 `migrate`를 거쳐 한 배치로 실행하는데, 라이브러리 코드(`executeHranaBatch`)상 `BEGIN → 문장들 → COMMIT`이고 실패하면 `ROLLBACK`한다. **운영에서 실패를 일부러 일으켜 본 적은 없다.**

### 3.2 대상 DB

운영 VM 앱 폴더의 `.env` 두 곳이 정의한 `TURSO_DATABASE_URL`의 지문(`sha256(URL.trim())` 앞 8자리, 하네스와 같은 계산)이 모두 **`6e5256b8`**이다(두 번 관측). 원격 T1~T7과 백업을 한 대상의 지문도 `6e5256b8`이다. 즉 지문 기준으로 **원격 시험은 운영 VM이 설정한 DB에서 수행됐다.** 실행 중 앱이 이 `.env`를 읽는지는 프로세스 환경에 이 변수가 없다는 점에서 추정한 것이며 직접 확인하지 않았다.

### 3.3 병합 직전 백업과 사전 상태 확인 — 수행함 (2026-10-02, 운영 DB에는 읽기만)

## 6. 시각 승인: 승인 범위와 검증 한계

사용자가 승인한 것은 **현재 구현의 시각 상태**다(`progress.md` D-NEW-32, `approval/APPROVAL-PACK.md` §6 결정 5). 사용자 지시에 따라 같은 승인을 PR 댓글이나 새 질문으로 다시 받지 않는다. 상세 표는 `approval/APPROVAL-PACK.md` §6.1이다.

**승인 범위**: 코드 트리 `aed7dab`(그 뒤 커밋은 문서·캡처만 변경)가 렌더링하는 상담 화면의 현재 시각 상태. 앞서 사용자가 따로 정한 결정이 모두 이 상태에 들어 있다.

| 결정 | 상태 |
|---|---|
| 03-D `handoff_mismatch` 문구(제목·부제)와 구성(요약 카드 + "이전 화면으로 돌아가기"만) | 사용자 승인(현재 그대로) |
| 연락처 표시 | `handoff_mismatch`만 가려서 표시(`010-****-5678`). `unknown_outcome`은 원문 그대로 |
| `.pen` 프레임 | 그리지 않고 시험으로만 검증 |
| "입력 내용 · 유지됨" 문구 | 필수 동의 재확인 안내를 덧붙임 |
| **시각 정합 승인** | **승인됨(현재 구현).** 시각 정합 완료·병합 가능·운영 준비·독립 감사 통과를 뜻하지 않는다 |

**검증 한계(승인 범위 안에서 게이트와 측정이 보지 못한 것)**

1. **게이트가 측정하지 않는 축**: 03 계열 `skipMetrics` 5곳 — 03-B 성공 CTA, 03-C 중복 CTA, 03-D `retry`·`backCta`의 `left`·`width`, 모바일 M03 폼의 `top`. 이 축의 회귀는 `visual:verify`가 잡지 못한다.
2. **`.pen`에 없는 변형**: 03-D `handoff_mismatch`는 시각 게이트 대상이 아니고 단위 시험·e2e와 캡처 2장(Chromium, 전화 채널·시간 입력, 390px·1440px)으로만 확인했다.
3. **`.pen` ↔ 내보내기 비교의 시점**: "차이 0픽셀"은 문구 정렬 커밋 `a029261` 이전 파일 기준이고 그 뒤 파일로는 다시 비교하지 않았다.
4. **`.pen` 대조 범위**: 01·02 계열과 03·03-A2 폼 프레임은 직접 대조하지 않았다.
5. **미측정 상태**: 시간 미입력 카카오 성공 카드(3행), 카카오·시간 미입력의 03-D 캡처, 320px 같은 좁은 폭, Chromium 외 브라우저.
6. **허용 오차 ≠ 동일**: `visual:verify` 통과는 허용 오차(예: 03-D 3px/8px, M03-D 2px/4px) 이내라는 뜻이다.
