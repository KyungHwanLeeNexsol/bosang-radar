# 시각 정합성 비교 — SPEC-B2C-DIAGNOSIS-001 (D2 4차 재검증, 2026-09-20)

**이 문서는 이전 버전("D2 3차 재검증")을 완전히 대체한다.** 4차 외부
재검토는 3차 라운드가 프레임 크기·일부 폭·모바일 배경·푸터 조건은
개선했지만, 공통 `justify-center` 세로 중앙 정렬 때문에 짧은 화면
(01-D/E 등)일수록 콘텐츠가 디자인보다 100~180px 아래로 밀렸고, 캡처
스크린샷에 Next.js 개발 도구 배지("N"/"1 Issue")가 찍혀 있었으며,
"미승인 시각 차이 0건"이라는 결론이 실제 스크린샷과 모순된다고 정확히
지적했다. 이 문서는 그 지적을 반영해 디자인·구현 양쪽의 실측 bounding
box를 대조한 결과이며, **PASS로 포장하지 않고 허용 오차를 벗어난 항목은
그대로 미해결로 남긴다.**

## 측정 방법론 (4차 개선)

1. **Next.js 개발 도구 배지 원인과 해결**: `<nextjs-portal>` 커스텀
   엘리먼트가 `next dev` 모드에서 항상 렌더링되는 Next.js DevTools
   인디케이터임을 직접 확인했다(오류·경고와 무관하게 dev 모드에서는
   항상 나타난다 — 코드 결함이 아니다). 해결: 이번 라운드의 모든 캡처는
   `pnpm build && pnpm start`(프로덕션 빌드+서빙)로 수행했고, 프로덕션
   페이지에 `document.querySelector("nextjs-portal")`이 `null`임을
   Playwright로 직접 확인한 뒤에만 캡처를 진행했다.
2. **세그먼트 기반 디자인 실측**: Playwright+Canvas로 `design/exports`
   PNG를 50% 정규화한 뒤, 배경과 다른 "콘텐츠" 픽셀 행을 quiet-gap 기준
   블록으로 분리하는 스크립트를 작성해 각 화면의 주요 요소(배지·스피너·
   아이콘·제목·옵션 행 등) top/left/width/height를 좌표로 뽑았다. 사용자가
   제시한 5개 참조값(01-C=145, 01-D/E=174, M01-B=78/79, M01-C=87/88)과
   전부 오차 0~2px로 일치해 이 방법론의 신뢰도를 교차검증했다.
3. **DOM 정밀 측정(구현 쪽 1차 근거)**: 구현 화면은 프로덕션 서버에
   Playwright로 접속해 `getBoundingClientRect()`로 각 요소의 실제 렌더링
   좌표를 측정했다 — 픽셀 스캔이 아닌 브라우저 레이아웃 엔진의 실측값이므로
   이 문서의 "구현" 열은 이 방법이 1차 근거다.
4. **모달/시트 전용 측정**: 반투명 오버레이 뒤로 원 페이지 요소가 비쳐
   보여 일반 배경-차이 스캔이 오염되는 문제를 확인했다 — 대신 흰색(RGB
   235 이상) 밝기 임계값으로 모달/시트 박스 자체의 경계만 검출하는 별도
   스크립트를 썼다.
5. **허용 오차**: Desktop 8px, Mobile 4px. 이 오차를 넘는 항목은
   구조적으로 "일치"라고 기록하지 않으며, 아래 §허용오차 초과 항목에
   그대로 미해결로 남긴다.
6. **재사용 없음**: 10개 대상 화면 전부 이번 라운드 코드 수정 후 프로덕션
   빌드로 새로 캡처했다. 정규화 이미지·세그먼트/DOM 측정 스크립트는 검증
   전용 임시 파일로만 사용하고 커밋하지 않았다.
