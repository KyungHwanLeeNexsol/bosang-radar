# 시각 정합성 비교 — SPEC-B2C-DIAGNOSIS-001 (D2 7차, 2026-09-21)

**이 문서는 이전 버전("D2 6차 재검증")을 완전히 대체한다.** 6차까지의 문서에
있던 PASS/FAIL 판정과 "PASS 근접"·"PASS(경계)" 같은 완화 범주는 전부
무효이며, 이 문서의 수치는 전부 이번 라운드에 커밋된 스크립트가 다시 측정한
값이다.

## 1. 이번 라운드가 바꾼 것

6차까지는 매 라운드 임시 스크립트를 만들어 측정하고 커밋 전에 지웠다. 그래서
(a) 결과를 재현할 방법이 없었고, (b) 비교 항목이 사실상 `top` 하나뿐이라
글자 크기·요소 폭·줄바꿈 지점의 어긋남이 드러나지 않았다.

이번 라운드는 검증 절차 자체를 저장소에 커밋되는 스크립트로 만들고, 그
스크립트로 실제 결함을 수렴시켰다.

- **검증 스크립트 커밋**: `scripts/visual-verify.ts` + `scripts/visual-verify-helpers.ts`
- **실행**: `pnpm visual:verify`
- **판정**: Desktop Δ ≤ 8px, Mobile Δ ≤ 4px의 **이진 PASS/FAIL**. 완화 범주는
  코드에도 이 문서에도 존재하지 않는다. 하나라도 초과하거나 상태/문구/줄바꿈이
  어긋나면 스크립트가 **exit 1**로 끝난다.

## 2. 실행 방법 (재현 절차)

```bash
pnpm visual:verify
```

선택 환경변수:

| 변수 | 용도 |
|---|---|
| `VISUAL_BASE_URL` | 이미 떠 있는 프로덕션 서버를 재사용(디버깅용). 미설정 시 스크립트가 직접 `pnpm build && pnpm start` |
| `VISUAL_SKIP_BUILD=1` | 빌드를 건너뛰고 기존 `.next`로 start만 |
| `VISUAL_ONLY=01,M01-C` | 지정한 화면만 검증 |

스크립트는 `ENABLE_DIAGNOSIS_DEV_STATES=true`를 **자기 자신이 띄우는 서버
프로세스에만** 주입한다(별도 사전 설정 불필요). 산출물은
`.moai/reports/visual-check/SPEC-B2C-DIAGNOSIS-001/` 아래
`screenshots/`, `normalized-design/`, `overlays/`, `diffs/`,
`measurements.json`에 기록된다.

## 3. 측정 방법론

1. **프로덕션 캡처 강제**: 캡처 대상은 항상 `next build` + `next start`다.
   매 화면 캡처 직전 `page.locator("nextjs-portal").count() === 0`을 단언해
   개발 서버 캡처를 차단한다(10개 화면 전부 0 — §5 표의 `portal` 열).
2. **동일 좌표계·동일 알고리즘**: 2배 해상도 디자인 export를 Chromium
   `<canvas>`에 50%로 그려 1배로 정규화하고, 구현은 디자인과 **정확히 같은
   1배 viewport**로 캡처한 뒤, **같은 ink-pixel 세그먼트 함수**를 두 이미지에
   적용한다.
3. **요소 식별과 측정의 분리**: 구현 쪽은 DOM locator로 요소를 *식별*하고,
   그 DOM 영역 안의 *잉크*를 측정한다. 6차가 지적받은 "디자인은 ink,
   구현은 line-height box" 혼용을 이 구조로 제거했다.
4. **저대비 상자용 2차 임계값**: 옅은 테두리·옅은 배경 상자는 기본 임계값
   (18)으로는 안쪽 글자만 잡힌다. 그런 요소는 임계값 6을 **디자인과 구현
   양쪽에 동일하게** 적용한다(같은 알고리즘 원칙 유지).
5. **애니메이션 정지**: `reducedMotion: reduce` + 캡처 직전
   `animation: none / transition: none / caret-color: transparent` 주입.
   오버레이 열림 전이가 끝난 뒤에 주입해 Drawer/Dialog 마운트를 방해하지
   않는다.
6. **단계 상태 고정(01-C/M01-C)**: 고정 sleep을 쓰지 않는다.
   `?devStep=loading&devStage=1`로 단계를 고정한 뒤, 세 행의 상태 문구가
   `완료 / 진행 중 / 대기`임을 DOM에서 직접 확인하고 캡처한다.
7. **측정 축**: 요소마다 `left / top / width / height` 4축 + 줄 수 +
   줄바꿈 지점(글자 단위 rect 묶음) + 상태 문구 + 배경색을 기록한다.
   의미가 달라지는 항목(상태 문구·문구 원문·줄바꿈 지점)은 픽셀 허용 오차와
   무관하게 **정확히 일치**해야 한다.

## 7. 이번 라운드에 바로잡은 실제 결함

1. **Pretendard가 로드되지 않고 있었다**(근본 원인). `pretendard`가 의존성에
   있는데도 어디에서도 import되지 않았고 `--font-sans`는 `var(--font-sans)`
   라는 순환 정의였다 — 한글이 OS 기본 폰트로 폴백 렌더링돼 같은 문자열의
   글자 폭·잉크 높이가 디자인과 어긋났고, **줄바꿈 지점이 캡처 머신에 설치된
   폰트에 좌우돼 시각 검증 자체가 재현 불가능했다.** 이미 설치돼 있던
   Pretendard Variable을 실제로 연결했다(신규 의존성 없음).
2. **01-C/M01-C를 디자인과 다른 단계 상태로 캡처하고 있었다.**
   `?devStage=`로 단계를 고정하고 캡처 전 상태 문구를 DOM에서 확인한다.
3. **Desktop 푸터가 본문과 다른 폭이었다.** 디자인 푸터는 본문과 같은 760px
   중앙 컬럼 안에 있고 구분선도 그 구간에만 그어진다 — 구현은 화면 전폭이라
   링크·면책 문구가 디자인보다 300px 이상 좌측에 있었다.
4. **Mobile 히어로/질문/안내/링크가 중앙 정렬이었다.** 디자인은 좌측 정렬이다.
5. **Mobile 좌우 여백이 16px이었다.** 디자인 실측은 20px.
6. **주의 배너에 디자인에 없는 제목 줄이 있었다.** 디자인에서 강조되는 부분은
   문장 앞 절("이름 · 전화번호 · 주민등록번호 등")이고 나머지가 본문이다.
   제목/본문이 블록으로 분리돼 있어 좁은 폭에서 배너 높이도 커져 있었다.
7. **동의 모달/시트 CTA가 auto 폭이었다.** 디자인은 안쪽 폭을 꽉 채운다.
8. **Mobile 전용 문구를 쓰지 않아 3줄이 되고 있었다.** M01 설명·M01-B 답변
   안내·M01-C 제목이 Desktop 문구 그대로라 좁은 폭에서 한 줄씩 더 늘어나
   이후 요소가 전부 아래로 밀렸다.
9. **옵션 행 높이가 디자인보다 커 4행 누적 편차가 있었다**(6차 미해결 항목).
10. **글자 크기 추정치가 실제와 달랐다.** Pretendard 로드 후 같은 문자열의
    잉크 폭으로 역산해 화면별로 바로잡았다(§5 표의 `글자` 열).

**접근성 영향 없음**: M01-C에서 시각적으로 감춘 단계 상태 문구는 `sr-only`로
접근성 트리에 그대로 남아 있고, 옵션 행 54px는 44px 최소 터치 타깃을 넘는다.
D1의 `?step=`/히스토리 로직, 상태 전이, 이전/다음/건너뛰기 기능은 이번
라운드에서 전혀 건드리지 않았다.

## 8. 잔여 위험 (허용 오차 초과가 아닌 것)

- **M01-C의 지배 배경색 판정**: 디자인 #f4f6f8 / 구현 #ffffff로 다르게
  나왔다. 이 화면은 흰 카드(단계 행 3개 + 스켈레톤 2장)가 차지하는 면적과
  회색 페이지 배경 면적이 거의 같아 최빈색 판정이 뒤집히는 구간이다 — 페이지
  배경 토큰은 다른 Mobile 화면(M01·M01-B)과 동일하게 `app-bg`(#f4f6f8)이며,
  각 요소의 좌표·크기는 전부 허용 오차 이내다. 실제 색 결함이 아니라
  측정 방식의 경계 사례로 기록한다.
- **01-A2 제목의 측정 경계**: 이 요소의 잉크 박스에는 같은 높이에 있는 닫기(X)
  버튼이 함께 들어간다(디자인·구현 모두 동일). 따라서 이 행의 폭 비교는
  "제목 좌측 시작점 ~ 닫기 버튼 우측 끝"을 비교하는 것이며, 순수한 제목 텍스트
  폭만 비교하는 것이 아니다.
- **`.pen` 원본 미접근**: 글자 크기는 이제 추정이 아니라 동일 문자열의 잉크
  폭에서 역산한 값이지만(따라서 재현 가능), 디자이너가 지정한 정확한 값과
  1px 미만 차이가 있을 수 있다. 소수점 px 값(14.35px 등)이 남아 있는 이유다.
- **회전 애니메이션 요소**: 스피너는 애니메이션을 CSS로 정지시켜 기준 상태로
  고정했으므로 재현 가능하지만, 기준 상태의 호(arc) 모양이 디자인의 "C" 형태와
  완전히 동일하지는 않다(Δ는 허용 오차 이내).
- **질문 문구 의존**: M01-B 제목의 줄바꿈 지점 검증은 현재 placeholder 질문
  문구에 묶여 있다. 매칭 엔진 연결로 질문이 동적으로 바뀌면 이 검증 항목은
  갱신이 필요하다.
