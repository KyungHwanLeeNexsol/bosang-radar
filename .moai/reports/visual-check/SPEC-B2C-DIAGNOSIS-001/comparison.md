**이 문서는 이전 버전(M-fix 재검증)을 완전히 대체한다.** 이전 버전 작성

(진행률 바·확인 배지·스켈레톤 카드·아이콘 등 export에 있는 요소가

**일치**(export와 구조적으로 동일하게 확인됨) / **허용된 차이**(SPEC 범위·
요구사항에 근거한 의도된 차이, 근거 명시) / **미해결**(export와 다르며
아직 해소되지 않음). 구조적으로 확인하지 않은 항목을 "일치"로 표기하지
않는다.

design.md §16 절차에 따른 수동 비교 기록이다. 자동 픽셀 diff 도구는 도입하지
않았다(tech.md § 비용 태도, design.md §16) — Playwright로 각 상태를
`?devStep=`(또는 실제 사용자 플로우)으로 강제 진입해 캡처한 스크린샷과
`design/exports/`의 대응 PNG를 나란히 놓고 레이아웃 폭 · 색상 토큰 · 텍스트
· 구조 일치 여부를 수동으로 리뷰한 결과다.

## 잔여 위험 (범위 밖으로 남겨둠 — 은폐하지 않고 명시)

1. **동의 상세 6개 문구는 여전히 리터럴 placeholder다.** 법무 확정 전까지 의도된 상태이며(AC-B2CDIAG-025), 이번 수정에서도 실제 문구를 임의로 작성하지 않았다.
2. **질문 문구(01-B)는 대표 placeholder다.** 매칭 엔진 미연결 상태이므로 design.md §15 각주와 기존 progress.md 잔여 위험 기록 그대로 유지된다. "다음 질문" 힌트 라벨(shortLabel)도 이 placeholder 질문 세트에 종속되어 있다.
3. **자동 픽셀 diff는 여전히 도입하지 않았다.** 수동 리뷰 절차이며 미세한 여백·폰트 렌더링 차이는 육안 검토 범위를 벗어날 수 있다.
4. **`pnpm vitest run --coverage`는 이 Windows 워크트리에서 0/0으로 보고되는 기존 환경 갭이 재확인됐다.** 첫 번째 리미디에이션 라운드에서 이미 기록된 문제와 동일 증상이며, 이번 라운드에서 새로운 원인을 발견하지 못했다 — §E 자체검증 항목 참고.

- 정밀 픽셀 diff 자동화는 이 SPEC에서 결정하지 않는다(design.md §16 그대로 유지).
