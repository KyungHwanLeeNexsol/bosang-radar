# 시각 정합성 비교 — SPEC-B2C-DIAGNOSIS-001 (D2 3차 재검증, 2026-09-20)

**이 문서는 이전 버전("D2 재검증, second remediation round")을 완전히 대체한다.**
3차 외부 재검토는 이전 판정이 "배지·진행 바·아이콘 요소가 존재하는가"만
확인했을 뿐, `design/exports/*.png`가 **2배 해상도**로 export되어 있어
raw PNG 픽셀 크기를 1배 Playwright viewport와 직접 비교하면 안 된다는
점을 놓쳤다고 지적했다. 이 문서는 그 지적을 반영해 **50%로 정규화한
1배 프레임**을 기준으로 처음부터 다시 검증한 결과다.

## 측정 방법론

1. **1배 프레임 크기 확정**: `design/exports/*.png`의 raw PNG를 IHDR
   청크로 직접 읽어 2배임을 확인하고 50%로 나눈 값을 프레임 크기로
   확정했다(아래 표). 사용자가 제시한 확인된 1배 기준과 완전히 일치한다.
2. **`.pen` 교차검증 — 불가**: 이 실행 환경에는 Pencil 데스크톱 앱이
   연결되어 있지 않아(`mcp__pencil__read_skill` 호출 시
   "failed to connect to running Pencil app" 오류) `.pen` 프레임 bounds와
   typography 수치를 직접 조회하지 못했다. 이 문서의 "콘텐츠 폭"·
   "제목 크기" 수치는 `.pen` 소스 진실이 아니라 아래 2/3번 방법의
   근사치이며, 이 한계를 숨기지 않고 명시한다(§ 잔여 위험 참고).
3. **자동 픽셀 스캔(보조 신호)**: Playwright+Canvas로 배경색과 무관한
   "콘텐츠" 픽셀의 행별 연속 구간(40px 미만 잡음 제외)을 스캔해
   중앙값/90퍼센타일 폭을 계산하는 스크립트를 만들어, **동일한 알고리즘을
   디자인 export와 구현 스크린샷 양쪽에 똑같이 적용**했다(검증용 임시
   스크립트, 커밋하지 않음). 이 방법은 근접-배경색 요소(예: 01-D/E의
   옅은 안내 박스)나 거의 풀폭인 Mobile 레이아웃에서 신뢰도가 낮다는
   한계가 실측으로 확인됐다 — 아래 표에 신뢰도를 함께 표기한다.
4. **DOM 직접 측정(구현 쪽 1차 근거)**: 구현 화면은 `getBoundingClientRect()`/
   `getComputedStyle()`로 콘텐츠 폭·상단 Y·제목 font-size/line-height·
   배경색·푸터 유무를 **정확히** 측정했다(픽셀 스캔이 아닌 실제 렌더링
   값이므로 이 문서의 "구현" 열은 이 방법이 1차 근거다).
5. **육안 나란히 비교(1차 판정 근거)**: 10개 화면 전부를 디자인 export와
   구현 스크린샷을 나란히 놓고 배지·진행바·아이콘·간격·배경·버튼 위계를
   직접 대조했다. 자동 측정치가 불안정한 화면(01-D/E, Mobile 풀폭 계열)은
   이 육안 대조가 실질적 판정 근거다 — "요소가 있다"가 아니라 "배치·
   크기·비례가 같다"를 확인했다.
6. **뷰포트 vs fullPage**: 전부 `page.screenshot({ fullPage: false })`
   (뷰포트 스크린샷)이며, IHDR로 실제 PNG 픽셀 크기가 목표 뷰포트와
   정확히 일치함을 재확인했다(아래 표의 "구현 캡처" 열).
7. **재사용 없음**: 이번 라운드는 기존 스크린샷을 인용하지 않고 10개
   대상 화면 전부(01/01-A2/01-B/01-C/01-D/01-E/M01/M01-A2/M01-B/M01-C)를
   코드 수정 후 새로 캡처했다. 정규화 이미지·픽셀 스캔 스크립트는 검증
   전용 임시 파일로만 사용하고 커밋하지 않았다.
8. **허용 오차**: 주요 bounding box 차이가 Desktop 8px, Mobile 4px를
   넘으면 "일치"로 기록하지 않는다 — 단, 위 3번 자동 측정이 신뢰도
   낮음으로 표시된 화면은 그 수치 하나만으로 미해결 처리하지 않고
   5번 육안 대조 결과를 우선한다(근거를 함께 명시).

## 화면별 육안 대조 근거 (1차 판정 근거)

- **01**: 헤더·히어로 카피·검색창·경고 배너·칩 6개·카드 4개 구조는
  기존과 동일하게 유지되며, 제목(26→32px)·검색창/CTA 높이(h-14→h-16)·
  Notice 패딩·칩 패딩·카드 패딩을 확대했다. `max-w-3xl`(768px)은
  자동 스캔 p90(758px)과 거의 일치해 폭 자체는 원래도 크게 틀리지
  않았음을 확인 — 이번 지적의 핵심은 세로 간격·타이포였다.
- **01-A2/M01-A2**: Desktop 모달 폭을 448→620px로 확대, 체크박스 행/CTA
  패딩 확대. Mobile 시트는 `h-[88vh]`(화면 위쪽까지 거의 채움) →
  `h-auto max-h-[85vh]`(콘텐츠 크기만큼만 차오름)로 변경 — 재캡처
  결과 디자인처럼 배경(01/M01 카드 1번까지)이 넉넉히 보이는 시트로
  바뀐 것을 스크린샷으로 직접 확인했다.
- **01-B/M01-B**: `max-w-md`(448px)→`max-w-[720px]`로 확대, 제목
  19→26px, 옵션 행 패딩 확대(`md:px-6 md:py-6`). 힌트 라벨 의미도
  수정했다 — 기존 "현재 질문→다음 질문"(Q1이면 "치료 여부→입원 여부")은
  디자인의 "다음 질문·입원 여부→사고 장소"와 의미가 달랐다. 이제
  "현재 질문 다음에 남은 질문들의 순서"를 보여주도록 고쳐 Q1에서
  정확히 "다음 질문 · 입원 여부 → 사고 장소"가 나온다(재캡처로 확인).
  Q1 문구도 디자인 대표 placeholder("무릎 골절로 수술을 받으셨나요?" +
  선택지 4개)로 교체해 "수술비·후유장해 담보 검토" 안내 문구와의 의미
  충돌도 해소했다.
- **01-C/M01-C**: 폭 확대(448→720px, 01-B와 동일), 제목 확대, 스피너
  크기 확대(size-9→md:size-11), 단계 행 패딩 확대. 캡처는
  `?devStep=loading` 진입 후 300ms 대기(STAGE_DELAY_MS=200ms 기준
  1단계 완료·2단계 진행 중 상태)로 고정 — design/exports와 동일한
  프레이밍이다.
- **01-D/01-E**: 최초 640px로 확대했을 때 제목("현재 입력만으로는
  보상 가능성을 판단하기 어렵습니다")이 "어렵습니"/"다"로 갈라져 2줄로
  꺾이는 문제를 재캡처로 발견했다(디자인은 1줄) — 01-B/C와 동일한
  720px로 재조정해 1줄로 복원했다(수정 후 재캡처로 확인). 아이콘
  실사용(SearchX/TriangleAlert, 빈 원형 span 아님), 안내 박스·버튼
  크기 확대(`md:h-11`, `md:px-7`)도 함께 반영했다.
- **모든 화면 공통 — 푸터**: `diagnosis-flow.tsx`에서
  `backgroundStep === "input"`일 때만(01/M01 및 그 위의 01-A2/M01-A2
  동의 오버레이) 푸터를 렌더링하도록 조건부로 바꿨다 — 01-B/C/D/E 및
  M01-B/C 재캡처에서 푸터가 사라진 것을 직접 확인했다(위 표 "푸터(구현)"
  열).

## 잔여 위험 (범위 밖으로 남겨둠 — 은폐하지 않고 명시)

1. **`.pen` 소스 직접 검증 불가.** 이 실행 환경에 Pencil 데스크톱 앱이
   연결되어 있지 않아(§측정 방법론 2번) 이 문서의 콘텐츠 폭·타이포
   수치는 정규화 PNG의 자동/육안 측정 근사치이지 `.pen` 원본 수치가
   아니다. Pencil 앱이 연결된 환경에서 재검증하면 미세한(수 px~10px대)
   차이가 발견될 수 있다.
2. **자동 픽셀 스캔의 알려진 한계.** §측정 방법론 3번·각주 1~3에 기록한
   대로, 오버레이 배경 위 콘텐츠(01-A2/M01-A2)·옅은 배경 박스(01-D/E)·
   거의 풀폭인 Mobile 레이아웃(M01 계열)에서 이 임시 스크립트의 수치가
   흔들린다. 이 문서의 1차 판정 근거는 육안 나란히 대조이며, 자동
   수치는 보조 신호로만 사용했다.
3. **동의 상세 6개 문구·질문 2/3 문구는 여전히 placeholder다.** 법무
   확정/매칭 엔진 연결 전까지 의도된 상태(AC-B2CDIAG-025, design.md
   §15)이며 이번 라운드에서도 임의로 확정하지 않았다.
4. **`pnpm vitest run --coverage`는 이 Windows 워크트리 조합에서
   0/0으로 보고되는 기존 환경 갭이 재현됐다** — §회귀 검증 참고, 근본
   원인 미규명(이전 라운드와 동일 계열).
5. **Mobile 배경 실측값(`#f4f6f8`)과 적용한 토큰(`app-surface-sub`
   `#f8fafb`)이 완전히 같지는 않다**(위 "배경색 참고" 참조) — `.pen`
   직접 접근이 가능해지면 재확인이 필요하다.
