# 시각 정합성 비교 — SPEC-B2C-DIAGNOSIS-001 (D2 5차 재검증, 2026-09-20)

**이 문서는 이전 버전("D2 4차 재검증")을 완전히 대체한다.** 5차 외부
재검토는 4차 라운드가 상단 정렬·프로덕션 캡처 전환·개발 도구 배지 제거는
잘 처리했지만, "미해결 2건만 남음"이라는 결론이 화면당 대표/외곽 요소
10~14개만 측정해 내린 것이라 내부 요소(제목·설명·행 간격·모달 내부
구조 등)의 실제 차이를 놓쳤다고 정확히 지적했다. 특히 01-A2 모달 높이
보정 방향이 반대로 기록돼 있었다(구현 260px가 디자인 270px보다 작은데
"더 줄이면 답답하다"고 적음). 이 문서는 화면별 내부 요소를 개별
bounding box로 재실측하고, 실제로 고친 뒤 재측정한 결과만 기록한다.

## 측정 방법론 (5차 추가)

1~4는 4차와 동일(세그먼트 기반 디자인 실측 + DOM 정밀 측정 + 모달/시트
전용 밝기 임계값 스캔 + `pnpm build && pnpm start` 프로덕션 캡처,
`nextjs-portal` 부재 확인). 5차에서 추가/정정한 것:

5. **화면당 대표 요소가 아니라 내부 요소 전체 측정**: 각 화면의 제목·
   설명·주 입력/패널·각 행 또는 카드·주요 CTA를 개별 selector로
   측정했다(§Bounding Box 비교표 참고).
6. **디자인 세그먼트는 ink-only, DOM은 line-height 박스라는 구조적
   차이를 인지**: 디자인 PNG 세그먼트 스캔은 글자의 실제 잉크 픽셀만
   감지하지만, DOM `getBoundingClientRect()`는 CSS line-height가 만드는
   전체 박스(잉크 위아래 여백 포함)를 반환한다. 이 때문에 제목처럼
   큰 폰트일수록 "디자인보다 아래로 처져 보이는" 차이가 구조적으로
   남을 수 있다 — 실제 렌더링 오류가 아니라 두 측정 방식의 근본적 차이이며,
   `.pen` 원본 접근 없이는 완전히 제거할 수 없는 잔여 위험으로 아래
   §허용 오차 초과 항목에 명시한다.
7. **overlay/diff 이미지 생성은 이번 라운드에서 완료하지 못했다** —
   아래 §완료 조건 대응에 정직하게 기록한다(잔여 작업).

## 일치로 판정한 항목 요약 (5차에서 새로 확인)

- **01 Desktop 검색+CTA 결합 컨트롤**: `md:gap-0` + 안쪽 모서리 radius
  제거로 텍스트 영역 오른쪽(968)과 버튼 왼쪽(968)이 정확히 맞닿는다.
- **01 세로 리듬 전체**: 안내 배너·칩 행·카드 그리드 top이 모두 디자인과
  1px 이내로 일치.
- **01-A2 모달 높이**: 270px로 디자인과 정확히 일치(방향 오류 정정 완료).
- **M01-A2 제목 2줄 wrap**: 디자인처럼 2줄로 줄바꿈.
- **M01 배경색**: `app-surface-sub`(#f8fafb, 오답)에서 이미 존재하던
  `app-bg`(#f4f6f8, 디자인과 정확히 일치)로 교체 — 새 토큰 추가 불필요.
- **01-B 옵션 행 1 위치**: 328px로 디자인과 정확히 일치.
- **01-D/01-E 제목·설명·안내 패널**: 전부 1px 이내로 일치.
- **검색창 textarea 전환**: `<input>` → `<textarea>`(`rows=2`,
  `[field-sizing:fixed]`)로 Mobile 95px 2줄 높이를 재현하고, 200자 제한·
  validation·autoFocus·controlled value·칩 자동입력 동작을 모두 유지.
  D1 테스트의 `querySelector("input")` 의존을
  `data-testid="diagnosis-search-textbox"` 기반 의미 selector로
  리팩터링했다(시나리오·기대값 변경 없음, 380/380 통과로 확인).
- **M01 모바일 카드**: "아이콘+제목 한 행/설명 한 행" 2단 구조로 재구성
  (디자인과 동일 구조), 번호(index)는 Mobile에서 숨김.
