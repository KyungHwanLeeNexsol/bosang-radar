## 1. 제품 정의

**사용자**: 보험 청구자 · 사고자 **본인** (전문가 아님)

**흐름**

```
본인의 사고 · 질병 · 담보에 대한 질문
        ↓
[진단 시작 동의] → 보상 진단 (실손 · 정액 담보 · 후유장해 · 특별 보상)
        ↓
연계 손해사정사에게 카톡 · 전화 상담 전달 (+ [상담 동의])
        ↓
접수 성공 / 중복 / 실패
        ↓
수임
```

**핵심 메시지** — "이것도 되고 저것도 되고, 이만큼이나 나온다"
실비 하나만 청구하고 끝내는 사용자에게 **놓치고 있던 담보를 전부 펼쳐 보여주는 것**이 제품의 전부입니다.

**참조 디자인**: KOICD 담보확인 페이지(`koicd.kr/insu/insu.do`) — 검색 → 코드 확인 카드 → 청구 가능 담보 그리드 → 면책 문구

## 4. 디자인 언어 (화면 02가 기준)

### 4카테고리 고정 프레임

사고든 질병이든 **답은 항상 이 4개**입니다. 내용만 케이스별로 교체됩니다.

| # | 카테고리 | 설명 |
|---|---|---|
| 1 | 실손 의료비 | 병원에 낸 돈을 돌려받음. **가입년도(1~4세대) 수집 배너 내장** |
| 2 | 정액 담보 | 진단 · 수술 · 입원마다 따로. 가장 많이 놓치는 부분 |
| 3 | 후유장해 | 금액이 가장 큼. **상담 CTA 배치 지점** |
| 4 | 특별 보상 | 배상책임 · 단체보험 등 내 보험이 아닌 곳 |

Desktop(`02`)은 4카테고리를 한 페이지에 전부 펼치고, Mobile(`M02`)은 화면이 좁아 카테고리를 **단일 선택 탭**으로 바꿔 한 번에 하나만 보여줍니다(`M02-B` 정액 담보 · `M02-C` 후유장해 · `M02-D` 특별 보상 — 실손 의료비는 `M02` 진입 시 기본 탭). 두 구조 모두 데이터 원본은 같습니다 — 레이아웃만 다릅니다.

### 결과 집계 기준 (현재 골절 사례 예시 데이터)

02/M02 상단 집계 배너에 쓰이는 숫자는 **현재 예시로 넣어둔 골절 사례 값**이며, 실제 구현에서는 항상 같은 분석 결과 데이터에서 자동 집계되어야 합니다.

| 상태 | 개수 | 의미 |
|---|---|---|
| 전체 분석 담보 | **15개** | 세 상태의 합계와 항상 일치해야 함 |
| 검토 대상 | 8개 | 사용자가 바로 확인해 볼 만한 담보 |
| 추가 정보 필요 | 6개 | 입력이 더 있어야 판정 가능 |
| 가능성 낮음 | 1개 | 해당 가능성이 낮은 담보 |

- `가입 여부 확인`은 결과 등급이 아니라 담보 카드 내부의 **보조 속성**입니다(가입 세대에 따라 갈리는 담보 등에 붙는 배지).
- 01-B 추가 질문의 답변은 **Fact Chip**으로 결과 카드에 그대로 연결됩니다 — 응답 없는 질문은 Chip을 만들지 않습니다.
- 03/M03 상담 신청 화면도 02/M02와 **동일한 분석 결과 데이터**를 사용합니다 — 상담 단계에서 숫자를 다시 계산하지 않습니다.

### 담보 카드 (`Coverage Item`)

3톤 상태 pill:

| 상태 | 배경 / 보더 | pill | 용례 |
|---|---|---|---|
| `검토 대상` | `$ok-soft` / `$ok-line` | `$ok` + 흰 글씨 | 사용자가 바로 확인해 볼 만한 담보 |
| `추가 정보 필요` | `$warn-soft` / `$warn-line` | `$warn` + 흰 글씨 | 입력이 더 있어야 판정 가능 |
| `가능성 낮음` | `$surface` / `$line` | `$surface-inset` + `$ink-4` | **해당 가능성이 낮은 담보도 노출** |

**가능성 낮음을 숨기지 않습니다.** "5대 골절 진단비 — 두개골·척추체·고관절만 해당, 무릎은 제외"처럼 왜 가능성이 낮은지 적습니다. 낮은 이유를 말해주는 쪽이 되는 것도 믿게 만듭니다.

> `청구 가능`/`조건부`/`해당 없음`은 초기 설계 당시의 구 표현이며, 현행 상태 정의가 아닙니다. §4 "결과 집계 기준" 표(검토 대상/추가 정보 필요/가능성 낮음)와 위 pill 정의가 SSOT입니다.

## 5. 금액 표기 정책 (유지)

B2C 대상이므로 단정형 금액 제시는 표시광고법 · 보험업법 리스크가 있습니다.

- **놀라움의 축은 금액이 아니라 담보 개수** — `11개 해당` / `4가지 보상 종류`
- 금액은 항상 **범위** (`약 300만 ~ 1,200만원`), 정액 담보만 단일 금액 + `정액 · 약관 확정`
- 면책 문구 필수 노출 — 숨기거나 툴팁 처리 금지
- 단정형 표현(`받으실 수 있습니다` 확정형) 금지 → `청구 가능` / `가능성` 표기

- 금액은 실제 값을 그대로 노출 — 클라이언트에서 재계산하지 않고 서버 산정값을 그대로 렌더링
- `평가 대기` 항목은 합계에 포함하지 않음 — 확정 항목과 미확정 항목의 합산 표기를 분리
- 면책 · 감액은 색상만으로 구분하지 않음 — 아이콘 + "면책"/"감액" 텍스트 라벨을 항상 함께 표기

## 6. 동의 구조

### 진단 단계 (01-A2 / M01-A2)

- 이름 · 전화번호는 **수집하지 않습니다**.
- 필수 동의는 **건강정보 등 민감정보 처리 동의 1건뿐**입니다. 일반 개인정보 수집·이용 동의와 마케팅 동의는 진단 단계에서 받지 않습니다.
- Desktop은 Modal, Mobile은 Bottom Sheet로 표시합니다.
- 「내용 보기」를 누르면 열리는 상세 구조는 `design/internal/DEV-ONLY-01-A3-*`에서 관리합니다 — 처리 목적 · 처리 항목 · 서버 저장 여부 · 보유기간 · 외부 AI 전송 여부 · 거부 시 제한 6개 항목이 확정 전 자리표시자(`{}`) 상태입니다.
- 상세 내용을 「확인」해도 동의 체크박스는 **자동 선택되지 않습니다** — 확인은 읽었다는 확인일 뿐입니다.

### 상담 단계 (03 / M03)

- 상담 신청을 위한 **개인정보 수집·이용 동의**(필수 ①).
- 진단 결과 등 건강정보를 상담에 이용하는 것에 대한 **동의**(필수 ②).
- **마케팅 관련 정보 및 안내 수신 동의**는 선택이며, CTA 버튼 활성화 조건에 포함하지 않습니다(필수 ① AND 필수 ②만으로 활성화).
- 같은 운영 법인 소속 상담 담당자는 **제3자가 아니라 내부 상담 담당자**로 처리합니다 — 별도 제3자 제공 동의가 필요 없습니다.
- 외부 손해사정사·제휴 법인 연결 구조가 실제로 생길 경우에만 제3자 제공 동의를 활성화합니다. 상세 조건은 `design/internal/DEV-ONLY-상담-신청-동의-상세-구조.png`에서 관리하며, 현재는 **미사용** 상태입니다.
- 실제 보유·이용 기간이 확정되기 전에는 사용자 화면에서 동의 상세를 **닫힌 상태로 유지**합니다 — 확정 전 추정치를 노출하지 않습니다.

## 7. 상담 신청 결과 상태 (03-B/C/D, M03-B/C/D)

| 상태 | 화면 | 처리 원칙 |
|---|---|---|
| 접수 성공 | `03-B` / `M03-B` | 체크 아이콘(ok). 상담 방식 · 연락처 · 희망 시간 · 담당자 표시 |
| 중복 신청 | `03-C` / `M03-C` | clock 아이콘(warn). 「기존 신청 상태 확인」+ 「진단 결과로 돌아가기」 CTA |
| 신청 실패 | `03-D` / `M03-D` | triangle-alert 아이콘(danger). 서버 저장 여부는 **단정하지 않음** |

신청 실패 화면은 다음 원칙을 사용합니다:

- `현재 화면에서 입력 내용이 유지됩니다` — "저장되어 있습니다"처럼 서버 보관을 단정하는 표현은 쓰지 않습니다.
- 재시도 버튼 제공.
- 이전 화면(진단 결과)으로 돌아가는 동선 제공.
- 입력했던 연락처와 희망 시간은 초기화하지 않습니다.

중복 판정 기준(동일 진단 결과 ID 또는 동일 연락처)은 서버에서 내려주며, 프런트는 응답 코드로 3상태를 분기합니다.

## 8. 폐기 이력 vs 현재 상태

기획이 여러 차례 바뀌며 아래 방향은 폐기되었습니다. **모바일은 예외입니다** — 한 차례 폐기됐다가 B2C 피벗 이후 다시 정식 범위로 들어왔습니다. 그 외 항목은 되돌아올 경우 git 이력에서 복구할 수 있습니다.

| 폐기 (과거 이력) | 내용 | 현재 상태 |
|---|---|---|
| **손해사정사 워크스페이스** | 사이드바 · 사건 관리 · 리서치 리포트 · 전문가 피드백 · 입증 서류 · 후유장해 트래커. 사용자가 전문가라는 전제였음 | 폐기 유지 |
| **3단계 동적 문진** | 사고 경위 → 진단·치료 → 가입 연도. 검색창 한 줄 입력으로 대체 | 폐기 유지 |
| **청구 주체별 결과 축** | 지자체 / 공단 / 보험사로 나눈 구조. **보장 유형별** 4카테고리로 대체 | 폐기 유지 |
| **손해사정사 영업 판단 바** | 예상 총 보상 · 고객 미인지 항목 · 수임 판단 · 상담 포인트 | 폐기 유지 |
| **모바일 390 버전** | 데스크톱 우선 정리 단계에서 한 차례 폐기 | **재도입됨.** 초기 모바일 시안은 한 차례 폐기되었으나, B2C 피벗 이후 현재 구조(§2 ④)로 재설계되어 정식 범위에 다시 포함됨. 현재 모바일 디자인을 폐기 상태로 읽지 말 것 |

구 `SPEC-funnel-dashboard.md`는 위 폐기분(대상 화면 표 · 화면별 구조 · 신규 컴포넌트 4종)만 담고 있어 전체 삭제했습니다. 그 안에 있던 금액 · 면책 표기 규칙만 §5로 옮겨 남겼습니다.

**현재 모바일 설계 원칙** (재도입 이후 확정):

- 질문 입력 · 동의 · 추가 질문 · 진단 중 화면을 Desktop과 동일하게 제공
- 결과는 4개 카테고리 **단일 선택 탭** — 한 번에 하나만 표시
- 하단 상담 CTA는 스크롤과 무관하게 유지(Sticky)
- 상담 신청과 성공 · 중복 · 실패 3상태를 Desktop과 동일하게 제공
- 동의 상세는 Modal이 아니라 **Bottom Sheet** 구조 사용
